**Blocked by:** 47 — 快捷键系统与重映射; 现有工具和菜单入口由对应旧票完成。未完成的命令仍可显示为禁用。

- [x] 菜单、图层蒙版命令、工具及子模式可搜索；整词、词首、缩写排序符合原版；禁用项不可执行。

## 实现说明（2026-10-13）

**匹配与排序（`lib/commands/palette.ts`）。** 原版 `CommandPaletteSearch`（CommandPalette.swift:32-99）
的逐行移植：查询里的空白忽略、字母按序出现即命中；每个字母计分（命中 +1、落在词首 +8、紧接上一个
命中 +5），再分五档——整段是词首（5）> 逐词词首（4）> 整段包含（3）> 去空格后包含（2）> 只剩散落
字母（1）——分数 = 档位 × 1_000_000 +（散落档才加 total × 100）− 标题长度 / 4；同分保持菜单顺序
（工具的模式才按 Tab 的顺序出现）。`palette.test.ts` 7 个用例，前五条照抄原版
`CommandPaletteTests`（字母按序/词首加权、整词优先于散落字母、逐词词首、可用项在前、无查询词按
菜单顺序），另加中文分档（CJK 没有空格，词首只能来自分隔符）与禁用项排在可用项之后。

**条目（`lib/commands/entries.ts`）。** 三类：菜单栏摊平成完整路径（「滤镜 › 高斯模糊…」）、
图层蒙版两条命令（原版 `layerCommands`：有选区时改名成"从选区添加 / 隐藏选区"）、工具与 24 条
子模式（原版 `tools`：液化是涂抹的模式、多边形套索是套索的模式，都不在菜单里）。重名命令的 id
追加出现序号（原版 `seen` 计数），同名不同路径互不影响；工具/蒙版命令的可用性分别按"有文档"与
"有活动图层且还没有蒙版"。14 个单测。

**共享菜单模型（`lib/commands/menuModel.ts` + MenuBar 发布）。** 原版面板每次打开重读 NSMenu，
所以动态标题（向下合并 / 合并组、创建 / 释放剪贴蒙版）与最近项目都是当下的值。Windows 这边菜单是
前端数据：MenuBar 用一个 `$effect` 把每次重算的菜单发布到 `menuModel`，面板搜索的就是菜单栏
此刻渲染的那份——标题、可用性、勾、快捷键（`hint` 来自 `chordFor + chordLabel`，改配即时更新）
不可能与菜单分叉。浏览器测试挂载真实 MenuBar，断言发布出来的菜单顺序、`视图 › 搜索命令…` 与它的
`Ctrl+F` 提示，以及面板确实搜到这份菜单。

**会话与结果（`lib/commands/session.ts`、`store.ts`）。** 打开时清空查询并回到第一行（原版每次
toggle 新建 model）；查询词只有真的变了才重置选择（原版 `query` 的 didSet：回车把同一段文字写回
不该让选择跳回第一行）；↑/↓ 两端环绕；执行前先关面板、把焦点还给打开前的控件，再跑条目——条目的
`run` 就是菜单项的 `run`，所以"命令执行后状态与普通菜单一致"是结构保证而不是巧合；禁用项不执行、
面板也不关（原版只响一声）。

**面板（`components/CommandPalette.svelte`）。** 460×290 居中（原版尺寸），搜索框在上、列表排到
下缘；勾显示开关状态、右侧显示当前快捷键、禁用行灰显且 `disabled`；无匹配显示"没有匹配的命令"；
选中的行滚进视野。按键挂在面板上（Tab 到某一行之后 Esc/↑/↓ 仍然有效，回车由行按钮自己的 click
触发、不会跑两遍）；点面板外等于原版"失焦即收"。面板还注册一条画布模态守卫：焦点落在面板空白处
时普通字母不穿透去切工具（原版面板是 key window，画布 keyDown 不响应）。

代码评审抓到的两处真实缺陷，都已修并各留一条浏览器回归（改回去测试就红，已实测）：

1. **Ctrl+F 的双重处理。** 焦点在结果行（`<button>`）上时，面板先关、事件继续冒泡到窗口分发器
   （`typingWins` 对"按钮 + Ctrl"放行菜单池），又被 toggle 回来 —— 净效果是"面板不关、查询被清空"。
   面板这一路现在 `stopPropagation`。
2. **画布池穿透。** 点面板空白会让 `tabindex=-1` 的面板容器拿到焦点，普通字母于是落到画布池切工具；
   现在面板开着时注册画布模态守卫。

**接线。** 定义表补上 `Menus:Search Commands`（`"f"` + Command，当前参考源码
KeyboardShortcuts.swift:92），Menus 46 → 47、全表 113 → 114，`table.test.ts` 的誊写期望同步；
动作表注册 `Menus:Search Commands` → `toggleCommandPalette()`；视图菜单加"搜索命令…"（原版在
View 组）；App 根上 `{#if $commandPaletteOpen}` 渲染面板。图层蒙版命令走
`state/layerMask.ts`（原版 `EditorSession.addMask` 的移植，复用 `Service.SetLayerMask` 与选区
取舍规则）。

**回归。** 单测 32 条（palette 7 / entries 14 / store 11）+ 快捷键分发 3 条（Ctrl+F 开关、焦点在
文本输入里让位、纯 F 不占用）+ 浏览器 11 条（列表与快捷键/勾、重名命令两条、动态过滤与无匹配、
↑/↓ 环绕、回车执行并关闭、Esc 与焦点返回、行聚焦时的按键、Ctrl+F 在行上不重开、画布键不穿透、
禁用项不可执行、未打开文档、MenuBar 发布同源）。浏览器用例挂的是真实 MenuBar 与真实窗口分发器
（`installAppShortcuts`），不是桩。

## 已知差异 / 留待后续

1. 原版 `skipped` 跳过 Window / Help / Services 三个 **macOS 系统菜单**；Windows 的"帮助"是本应用
   自己的菜单（检查更新…），是一条真命令，所以照列，只跳过面板自己的入口。
2. 原版的分工是 ⌘F 开面板、纯 F 切纯画布模式；本票只加 Ctrl+F，纯 F 留给票 55（已用测试钉住
   "纯 F 不占用"）。
3. 原版面板是 `NSPanel`（浮动、失去 key 即收），浏览器里对应"点面板外关闭 + 关闭时把焦点还给
   打开前的元素"。经**视图 ▸ 搜索命令…** 打开时，锚点（菜单按钮）随下拉一起从 DOM 移除，关闭后
   焦点落回 body —— 浏览器里画布命令走窗口级分发、不看 `activeElement`，行为与原版把窗口设回
   key 等价；Ctrl+F 路径（票面写的路径）则精确还原焦点。
4. 原版工具列表是 23 条（`NavigationTool` 的 15 个工具 + 模式），**没有**"无工具"；我们的工具轨有
   16 个（含"无工具"，A），面板照轨列全 —— 否则轨上的工具有一个搜不到。多出来的就这一条。
5. 原版 `canEditMask` 还含 `canEditLayers`（忙碌/导入中）与 `selectedLayerIDs.count == 1`：前端
   没有多选（活动图层即单选），忙碌由 Go 拒绝（DOCUMENT_BUSY）后 warn —— 与其它图层命令同一套
   处理，菜单项不做前端忙碌判断。
6. 定义表 113 → 114 是**照着当前参考源码**补的一条（票 47 的"113 条"是 v1.4.5 时代的表）；票 81
   （快捷键清除与旧配置迁移）落地时会再核对整表。
