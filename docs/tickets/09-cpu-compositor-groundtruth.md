### 先量后否掉的一个怀疑

`TestRenderMask` 的夹具只有 255 与 0，而 `multiplyCoverage` 有三条分支 —— 中间那条「按比例」看起来
没被它走到。变异（除以 510）一试：**被抓住了**，效果类用例（`TestRenderStrokeSoftMaskAndGroupOpacity`
等）覆盖了中间值。怀疑不成立，如实记下来。

### 查出并补上的缺口

`renderLayer` 里那段「剪贴源存在、但什么都没画出来 → 目标整层裁掉」的规则**没有任何测试**：把它改成
不动 `placed`，全部测试照样通过。后果不是报错，而是**底不可见时被剪贴的层整层显示**（实测 alpha 255）。

新增 `TestRenderClippingAgainstASourceThatRenderedNothing`：让源层 `IsVisible = false`（于是它不进
`scope.cov`），被剪贴的层必须每个像素 alpha 都是 0。加上之后重跑变异：立刻失败 ✓（「得到 alpha 255」）。

票面第 9 条写「剪贴链…各有像素级断言」—— `TestRenderClipping` 只覆盖了**正常底**，空底那条没覆盖。
那句话同样**说过头了**，这里按审计结果补全。

## 验收证据审计（2026-10-16，第四轮：混合模式的判别力）

这一层是像素不变量的核心，所以不只查「有没有测试」，而是查**现有期望值能不能分辨对错**。

| 变异 | 结果 |
| --- | --- |
| `BlendOverlay` 的两个分支对调 | ✗ **没被抓住 —— 真缺口** |
| `BlendHue` 退化成 `BlendLuminosity` | ✗ **没被抓住 —— 真缺口** |

### 缺口一：Overlay 的夹具是对称的

`TestBlendChannelFormulas` 里 Overlay 的两条用例是 `(d=0.25, s=0.5) → 0.25` 与
`(d=0.75, s=0.5) → 0.75`。**s = 0.5 时两个分支算出同一个值** —— 于是「实现正确」与「两个分支接反」
在表里完全无法区分。实测把分支对调，全部测试照样通过。

补两条 `s ≠ 0.5` 的用例（这才是这个模式的**定义性**测试）：`(0.25, 0.25) → 0.125`、
`(0.75, 0.25) → 0.625`。加上之后重跑变异：立刻失败 ✓。

### 缺口二：Hue 一条用例都没有

上面第 10 条写「24 种混合模式逐模式有参考用例」。实际核对下来：不可分模式里 Luminosity / Color /
Saturation 各有用例，**Hue 没有任何测试** —— 那一句是**说过头了**。新增
`TestBlendPixelHueKeepsTheBackdropsLuminance`：灰背景上的 Hue 混合应当保持那片灰（背景饱和度 0，
源的饱和度被压到 0）；背景有色相时结果的**明度等于背景的明度**。加上之后重跑变异：立刻失败 ✓。

### 一条方法上的话

断言存在 ≠ 断言吃劲。**对称的夹具**（在模式的定义性分支上恰好取到同一个值）看着像覆盖了，实际上
把「对」与「镜像」混为一谈。查这种缺口只能靠变异 —— 因为它不会让任何断言失败。
